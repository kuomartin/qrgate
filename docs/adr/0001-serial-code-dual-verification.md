# Serial Code：簽章 + Sheet 查表雙重驗證，金鑰各活動獨立

實體索票與貴賓票需要在活動前批次產生並列印，此時序號尚未（或剛要）寫入該活動的 Google Sheet。若序號只是隨機字串，任何人猜中或竄改都無法被識破；純查表也無法在批次產生的當下就確認「這是我們發的」。因此決定：Serial Code 除了在 Apps Script 端查該活動 Sheet 的使用狀態（防重複入場）外，也帶有以該活動專屬金鑰產生的簽章/雜湊（防偽造/防猜測），兩者在 check-in 時都要通過才算有效票。

金鑰不做全域共用，而是每場活動（各自的 Apps Script 部署）各自持有一組，存於該部署的 Script Properties。這與「一活動一 Apps Script + 一 Sheet」的既有架構一致：單一活動金鑰外洩不會波及其他活動，序號也不需要額外編碼活動 ID 來做活動隔離——用錯活動的金鑰驗證就會直接失敗。

Serial Code 不考慮人工辨讀／手動輸入的易用性，入場驗證完全以 QR 掃描為唯一手段。
